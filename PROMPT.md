# iOS Application Development Prompt

## 1. Информация о приложении

Название: [APP_NAME]

Идея: [APP_DESCRIPTION]

Категория: [APP_CATEGORY]

Основная функциональность: [FEATURES]

Стиль дизайна: [DESIGN_STYLE]

Разработай полноценное нативное iOS-приложение, готовое к сборке, тестированию и публикации в App Store.

## 2. Технические требования

- Язык: Swift
- UI: SwiftUI
- Минимальная версия: iOS 18.0
- Устройства: iPhone и iPad
- Архитектура: MVVM
- Хранение данных: SwiftData / UserDefaults по необходимости
- Использовать только стабильные системные API.
- Не использовать сторонние зависимости без необходимости.
- Проект должен открываться и собираться в Xcode.

## 3. Дизайн и интерфейс

Создай современный, качественный и уникальный интерфейс.

Требования:

- Индивидуальный дизайн приложения, а не стандартный шаблон SwiftUI.
- Продуманная цветовая палитра.
- Красивые карточки, кнопки, иконки и компоненты.
- Плавные анимации и переходы между экранами.
- Интерактивные элементы с визуальным откликом.
- Корректная адаптация под iPhone и iPad.
- Поддержка разных размеров экранов.
- Поддержка светлой и тёмной темы, если подходит концепции.
- Единый стиль всех экранов.
- Отсутствие пустых или незавершённых экранов.

Интерфейс должен выглядеть как законченный коммерческий продукт, а не демонстрационный проект.

## 4. Функциональность

- Реализовать все основные функции приложения.
- Все кнопки должны работать.
- Все переходы должны вести на соответствующие экраны.
- Сохранять необходимые пользовательские данные.
- Корректно обрабатывать ошибки и пустые состояния.
- Обеспечить корректную работу после перезапуска.
- Не использовать фиктивную функциональность.

## 5. Архитектура проекта

Организовать проект по структуре:

- App
- Models
- Views
- ViewModels
- Components
- Services
- Resources
- Utilities
- Tests

Разделить интерфейс, бизнес-логику и хранение данных.

Не создавать один огромный Swift-файл.

## 6. Анимации

- Использовать нативные SwiftUI Animations.
- Добавить плавные переходы между состояниями.
- Анимировать основные действия пользователя.
- Исключить резкие скачки интерфейса.
- Обеспечить стабильную производительность анимаций.

## 7. Тестирование

Обязательно реализовать:

- Unit Tests для основной логики.
- UI Tests для ключевых пользовательских сценариев.
- Тесты сохранения и загрузки данных.
- Проверку переходов между экранами.
- Проверку обработки ошибок.
- Тестирование интерфейса на iPhone и iPad.

Все созданные тесты должны запускаться в Xcode.

## 8. Качество реализации

- Не оставлять TODO.
- Не использовать заглушки вместо рабочих функций.
- Не оставлять неиспользуемый код.
- Избегать deprecated API.
- Не допускать утечек памяти.
- Обрабатывать состояния загрузки и ошибки.
- Соблюдать актуальные рекомендации Apple.
- Добавить необходимые Privacy Usage Descriptions при использовании защищённых API.

## 9. Финальная проверка

После разработки:

1. Проверить структуру проекта.
2. Проверить компиляцию.
3. Исправить найденные ошибки.
4. Запустить Unit Tests и UI Tests.
5. Проверить интерфейс на iPhone и iPad.
6. Проверить каждую основную функцию.
7. Убедиться, что приложение готово к дальнейшему релизному тестированию.

Если инструменты сборки или симуляторы недоступны, не утверждать, что проверки выполнены.

## 10. Результат

Предоставить полноценный Xcode-проект со всеми необходимыми файлами, экранами, ресурсами и тестами.

Не ограничиваться примерами кода.

Главное правило: приложение должно быть полностью реализовано, визуально завершено и функционально готово к использованию.
